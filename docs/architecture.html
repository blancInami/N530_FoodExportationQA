系統概述

本系統為食品輸銷知識問答平台，基於 RAG（Retrieval-Augmented Generation） 架構，整合向量資料庫、Aho-Corasick 自動機、大型語言模型與官方雙語術語字典， 提供精準的中英雙語食品輸銷問答服務。

🔍 輸入處理

支援中英文混合輸入。英文自動 LLM 翻譯後進入中文語境的意圖分類與向量搜尋。DictionaryMatcher 其後會對查詢進行特徵擴增。

🗄️ 雙軌知識檢索

Track A：PostgreSQL + pgvector 雙路徑向量搜尋（題目 + 回覆）。Track B：知識文獻庫內容向量搜尋，依文獻類型（REGULATION / GUIDELINE / QA）格式化 XML 區塊。兩軌結果 Python 層依距離全局合並。

🤖 雙語生成

DictionaryMatcher 動態篩選命中術語，如有知識文獻命中則附加 <Knowledge_References> 區塊，以 XML Prompt 注入 LLM，生成英文 + 繁體中文雙語回覆。

問答管線（/qa/ask）

問答請求依序經過四大階段（Phase 1 細分 a/b/c 三層），各階段均為非同步操作， 最終回傳 9 欄位扁平化 AskResponse。

Phase 1
輸入
前處理
1a — 語言偵測 & 翻譯
  • 偵測輸入是否含中文（Unicode 範圍判斷）
  • 若非中文 → chat_completion() 翻譯為繁體中文（chinese_query）
1b — 意圖分類（雙層）
  • Layer 1：get_intent_classifier(session) 返回 Aho-Corasick 比對器（lazy-load 單例）；掃描 chinese_query 中的分工關鍵字 → 返回「機關」+「單位」對
  • Layer 2：Aho-Corasick 無命中時觸發 llm_fallback_classify()；將「單位對照表」全量列（編號清單格式）完整提供給 LLM，請其輸出 JSON 格式機關/單位；兩層均無結果時回傳 None
1c — 特徵擴增
  • get_dictionary_matcher(session) lazy-load（與 Phase 3 共用 singleton，零 DB round-trip）
  • matcher.filter_by_text(chinese_query) 命中術語，取前 5 筆附加至查詢
  • 輸出 enriched_query，無命中時退化為 chinese_query
↓
Phase 2
雙軌
檢索
Embedding：enriched_query → 1024-dim 向量

Track A — 問卷庫（見「向量檢索」章節）
  • 雙路徑向量搜尋 → UNION ALL → GROUP BY 聚合 → HAVING 距離閾值
  • CROSS JOIN 展開相鄰切塊（±1）→ JOIN 問卷題目檔 & 問卷主檔
  • JOIN 問卷附件檔 取得附件路徑（全參數化）
Track B — 知識文獻庫
  • cosine_distance 內容向量 → 聚合 → HAVING 閾值
  • CROSS JOIN 展開相鄰切塊 → JOIN 知識文獻節點檔（取節點標題路徑）→ JOIN 知識文獻主檔
  • 產生 knowledge_context：依 REGULATION/GUIDELINE/QA 類型格式化 XML 區塊
全局合並：依 RETRIEVAL_MERGE_MODE 環境變數決定策略
  • independent（預設）：兩軌各自獨立保留 top_n，知識文獻不被問卷擠出
  • compete：兩軌混排後共用 top_n 配額（依 min_distance 全局排序）
↓
Phase 3
LLM
生成
DictionaryMatcher 動態篩選（見「字典機制」章節）
  • 複用 Phase 1c 已載入的 singleton，零成本
  • matcher.filter_by_text(chinese_query, raw_context) 掃描命中術語
  • build_dictionary_xml(filtered_dict) 組 <Mandatory_Dictionary> XML
LLM 呼叫
  • Prompt 含問題原文、問卷上下文、XML 術語字典
  • 若有知識文獻命中，附加 <Knowledge_References> 區塊（依文獻類型標注來源）
  • chat_completion() → 解析 --- 分隔線 → (英文回覆, 中文回覆)
↓
Phase 4
回傳
組裝
  • s2t(中文回覆) — OpenCC 確保正體中文
  • 組裝 9 欄位 AskResponse：負責單位、原始題目、中文譯文、中文回覆、英文回覆、附件超連結、參考來源、知識參考來源
  • 無問卷且無知識文獻命中時提前返回「無法作答」訊息

向量檢索 CTE 鏈

所有查詢使用 SQLAlchemy Core 表達式，以 .cte() 鏈式組合，杜絕 Raw SQL 字串拼接。雙軌並行執行後在 Python 層全局合並。

Track A — 問卷庫（9 層 CTE）

CTE 名稱說明
title_hitscosine_distance(題目向量)，取 top_k 筆，含 chunk_idx
reply_hitscosine_distance(回覆向量)，取 top_k 筆
combinedUNION ALL 合併雙路徑結果
aggregatedGROUP BY 問卷題目檔主鍵 + chunk_idx，MIN(distance)，HAVING <= threshold，LIMIT top_n
adjVALUES(-1), (0), (1) — 相鄰偏移量
expandedCROSS JOIN aggregated × adj，計算 target_idx
expanded_chunksJOIN 問卷題目切塊 取切塊文字
final_dataJOIN 問卷題目檔（是否刪除=0）取題目序號
主查詢JOIN 問卷主檔 取問卷名稱/輸出國家/輸出品項；.in_() JOIN 問卷附件檔

Track B — 知識文獻庫（6 層 CTE）

CTE 名稱說明
knowledge_hitscosine_distance(內容向量)，取 top_k 筆
knowledge_aggGROUP BY 知識文獻節點檔主鍵 + chunk_idx，MIN(distance)，HAVING <= threshold，LIMIT top_n
knowledge_adjVALUES(-1), (0), (1)
knowledge_expandedCROSS JOIN knowledge_agg × knowledge_adj，計算 neighbor_idx
knowledge_expanded_chunksJOIN 知識文獻切塊檔 取切塊內容
knowledge_finalJOIN 知識文獻節點檔（取節點標題路徑）→ JOIN 知識文獻主檔（取文獻名稱、文獻類型）
距離閾值：使用 cosine distance（<=> 運算子），預設 SIMILARITY_THRESHOLD=0.75。 值越小代表越相似。可透過 API 參數 similarity_threshold 覆蓋。
禁止：CTE 別名不可使用 PostgreSQL 保留字（offset、limit、order）。

檢索合併模式（RETRIEVAL_MERGE_MODE）

Track A（問卷庫）與 Track B（知識文獻庫）完成各自 CTE 查詢後， Python 層依 settings.retrieval_merge_mode 環境變數決定如何合並兩軌結果。

independent  預設模式

兩軌各自獨立保留 top_n 筆，彼此不佔用名額。

適用場景：問卷庫與知識文獻庫均有豐富資料，希望兩軌結果都能完整呈現。

final_q_rows = sorted(q_rows, key=lambda r: r["min_distance"])[:top_n]
final_k_rows = sorted(k_rows, key=lambda r: r["min_distance"])[:top_n]
# 合計最多 2 × top_n 筆

compete  競爭模式

兩軌結果混合排序後共用一個 top_n 配額。

適用場景：總回傳筆數有嚴格上限，優先展示距離最近的結果無論來自哪軌。

tagged = [(d, "questionnaire", r) for d, _, r in q_tagged]
       + [(d, "knowledge",      r) for d, _, r in k_tagged]
tagged.sort(key=lambda x: x[0])
tagged = tagged[:top_n]  # 兩軌共用 top_n 配額
設定方式：.env 中 RETRIEVAL_MERGE_MODE=independent（或 compete）。 top_k 不受此設定影響，始終由系統計算 max(TOP_K, top_n+25)，不暴露給使用者。

DictionaryMatcher 字典機制

「官方正規詞彙」資料表共 6000+ 筆中英對照術語。若全部注入 LLM Prompt， 約 200K+ tokens，嚴重超過 context window。 DictionaryMatcher 解決此問題：

運作原理

系統啟動後首次使用時，從 DB 載入全量詞彙，以 ahocorasick_rs.AhoCorasick 建構多模式字串搜尋自動機（O(n) 建構）。

每次問答時，對 chinese_query + raw_context 執行掃描，僅回傳命中的術語子集（~10–50 筆），注入 LLM Prompt。

效能對比

方式Token 用量
全量載入~200K tokens
DictionaryMatcher~500–2K tokens

節省 99% 字典相關 token 消耗，且不遺漏相關術語。

Singleton 模式

與 intent.py 的 IntentClassifier 相同設計：模組級 _matcher 單例，get_dictionary_matcher(session) 負責 lazy-load。

# utils/dictionary.py（簡化示意）
class DictionaryMatcher:
    async def load(self, session):          # 從 DB 載入全量詞彙，建構 automaton
        ...
    def filter_by_text(self, *texts) -> dict: # O(n) 掃描，回傳命中子集
        ...

_matcher = DictionaryMatcher()            # 模組級單例

async def get_dictionary_matcher(session): # lazy-load
    if not _matcher._loaded:
        await _matcher.load(session)
    return _matcher

模組責任說明

app/services/embedding.py

呼叫遠端 Embedding Server（OpenAI compatible），提供 get_embedding(text) 與 get_embeddings_batch(texts)，使用 httpx.AsyncClient。

app/services/llm.py

呼叫遠端 LLM Server，chat_completion(prompt, temperature, max_tokens)，使用 httpx.AsyncClient，timeout 可設定。

app/services/intent.py

IntentClassifier：雙層意圖分類器。

  • Layer 1：Aho-Corasick 比對「單位對照表」分工關鍵字（含 alias_mapping.json 別名），返回 IntentResult（機關 + 單位）
  • Layer 2：llm_fallback_classify() 僅在 Aho-Corasick 無命中時觸發；_all_unit_rows 於 load() 時轉存，無需再次查詢 DB；將全量列提供給 LLM，判斷無關聯時回傳 None

模組級單例 lazy-load。

app/services/retrieval.py

hybrid_retrieve(query, session, threshold, top_n)：
Track A：9 層 CTE 鏈式問卷庫向量查詢。
Track B：6 層 CTE 知識文獻庫向量查詢，依 REGULATION/GUIDELINE/QA 類型格式化 XML 區塊。
回傳 RetrievalResult（chunks、references、attachment_urls、raw_context、knowledge_context、knowledge_references）

app/services/ingest.py

ingest_questionnaire(pk, session)：讀取問卷題目檔 → 滑動視窗切塊 → tiktoken 計數 → DELETE 舊切塊 → Batch Embed → INSERT 向量。

app/services/translate.py

translate_with_dictionary(text, session)：DictionaryMatcher 篩選相關術語 → 組 XML → LLM 翻譯 → 返回英文字串。

app/services/breakdown.py

convert_file_to_markdown(path, ext)（同步，供 asyncio.to_thread）：以 MarkItDown 轉換 pdf/doc/xlsx 為 Markdown。
extract_questions(markdown)（async）：滑動視窗切塊 + Semaphore 限速並行 LLM 呼叫，萃取英文題號。

app/utils/dictionary.py

filter_by_text(*texts) → dict[str, str]（Phase 1c 特徵擴增）

  • Token 計數：優先使用 tiktoken cl100k_base；未安裝時以 len(text)//2 估算
  • 預設 max_tokens=1200（留 800 tokens 作 LLM 輸出緩衝）

開發規範

✅ 必須遵守

規範說明
SQLAlchemy Core only所有 DB 查詢使用 select()/insert()/delete()/update()，複雜查詢以 .cte() 組合
AsyncSession所有 DB 操作透過 get_db_session() 依賴注入的 AsyncSession
全參數化條件篩選使用 .in_(list) 等方法自動綁定參數
sanitize_text_for_db所有寫入 DB 的文字必須先清除控制字元
OpenCC s2t所有 LLM 中文輸出必須經 s2t() 轉換
向量寫入直接傳 Python list[float]，無需手動序列化
英文輸入先翻譯為繁體中文，再做意圖分類與向量搜尋

❌ 禁止事項

禁止行為原因
ORM（DeclarativeBase、session.add()）架構規範
f-string 拼接 SQLSQL Injection 風險
修改現有資料表欄位系統整合約束
CTE 別名使用 offset/limit/orderPostgreSQL 保留字
LLM 中文輸出不做 OpenCC可能出現簡體字
暴露 top_k 參數由系統計算 max(TOP_K, top_n+25)
tools/ 引用 app/ 模組獨立離線工具不得有主應用相依
